# 無料βの計測・実験基準

STEP 05の計測の正本。外部計測サービスや新規DBテーブルを追加せず、既存DBのサーバー保存時刻から集計する。現時点はローカルのダミー検証で、実参加者の実績ではない。

## 集計対象と定義

運営担当がβ協力者のUser IDだけを非公開JSON配列に記録する。メール・表示名・学習メモは不要。seed・開発者・自動テストを対象から除き、対象者IDかつ登録期間内のusersだけを集計する。IDの指定件数と登録期間内の実人数は別に出力する。

| 指標 | 定義・時刻 |
| --- | --- |
| 登録 | 対象usersの`createdAt`がfrom以上・to未満。メール確認完了やページ閲覧数とは別 |
| 初回受注 | `user_quests.acceptedAt`の最初の一件。観測期限より前のサーバー受注時刻 |
| 初回保存 | `study_logs.createdAt`の最初の一件。利用者指定の`studiedAt`は計測に使わない |
| 登録→初回保存48時間 | 登録から48時間未満の保存。48時間を観測し終えた登録者だけを分母にする |
| 7日再利用（D7） | 初回保存の日本時間の日をD0とし、D7の00:00以上・D8の00:00未満に新たな保存がある |
| D7の分母 | D8の00:00まで観測し終えた初回保存者。未成熟な人はpendingD7へ分ける |
| 離脱の手掛かり | 登録後に受注なし、受注後に保存なしの人数。操作失敗と意向の違いは聞き取りで確認 |

各利用者を1人として数え、複数ログや再送で人数を増やさない。D7は再ログインだけを再利用とは扱わず、学習保存で測る。分母0は0%ではなくnull（未評価）。JWT/Cookie/メール/メモ/個別ID/個別時刻は集計出力に含めない。

Prismaの`timestamp(3)`はUTC保存を前提とし、日本時間の暦日へ明示変換する。from/to/as-ofは`YYYY-MM-DD`の日本時間00:00。toとas-ofは排他的な上限。as-ofより後のログを除く。削除済みユーザーや過去に削除された記録は復元できず、現DBのsnapshotによる集計という限界がある。

## 実験案（公開前に日付・担当を確定）

- 初回は新規協力者10人を目標に、14日間の登録期間とその後14日間の観測を確保する。募集対象の分野は資格・技術・自己学習として聞き取り、公開後の反応で絞る。
- 登録→受注80%以上、登録→48時間以内の初回保存70%以上を目安にする。48時間の未成熟者は判断を保留。
- D7の観測済み母数5人以上で再利用40%以上を目安にする。5人未満は成功/失敗と断定せず、期間を延長するか募集条件を見直す。
- 未達なら離脱段階を確認し、AIや課金を追加する前に導線の改善を優先する。10人規模の数字で市場性や利益を証明したとは扱わない。
- 他人のデータ露出、重複報酬、保存喪失等の重大な不具合は募集停止・修正・再検証を優先する。月0円の費用停止条件は[release.md](release.md)に従う。
- 日程・担当・同意の確認後に実参加者を募集する。外部登録・公開・招待・メール送信は今回実施しない。

## 集計コマンド

`.local/beta-participants.json`へJSON配列を置く（`.local/`はGit除外）。次は説明用のダミーIDで、実データは運営者が取得したIDに置き換える。

```json
["participant-a-cuid", "participant-b-cuid"]
```

読み取り先の`DATABASE_URL`を非公開の環境設定へ入れ、できればSELECT専用DBユーザーを使う。接続URLをターミナル出力・PRへ載せない。次の過去日付も例で、実βの日付は未定。

```powershell
pnpm beta:report --participants .local/beta-participants.json --from 2026-01-01 --to 2026-01-15 --as-of 2026-01-29
```

`scripts/beta-metrics.mjs`は同じ接続で`REPEATABLE READ / READ ONLY`のtransactionと10秒のstatement timeoutを使い、SQL値をパラメーターで渡す。JSONには期間、参加者指定件数、集計件数、分子・分母・率だけを出力する。migration/seed/更新や外部送信を行わない。人数が少ない集計も運営者向けとし、参加者IDファイルや集計を無断で公開しない。

集計前に対象DB・日付・参加者一覧を確認する。参加者0件、重複ID、メール指定、不正日付、未来の観測日を拒否する。失敗時は個人情報や接続例外の全文を出さず、終了コード1にする。

## 検証と次の判断

`pnpm test:api:db`で参加者分離、登録期間、保存時刻と任意学習日の違い、日本時間D7の両端、重複ログ、48時間の両端、未成熟・空の分母、匿名出力を専用テストDBで確認する。所定の安全ガードでテストの接続先を制限する。

実βでは、集計と同時に「最初に迷った箇所」「保存できなかった理由」「翌週も使う理由」を聞き取り、個人の回答は指定した非公開先で管理する。優先改善と対象分野の決定、AI価値検証への着手は実績・公開ゲートを見て判断する。
