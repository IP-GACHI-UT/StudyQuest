# ローカル進捗表

[index.html](index.html)をダブルクリックするか、次のコマンドで開く。アプリ・DBの起動は不要。

```powershell
pnpm progress:serve
```

`http://127.0.0.1:4318/`で表示する。loopbackのみ待ち受け、`/`と`/index.html`だけを提供する。閲覧要求時にデータと文書から再生成する。外部通信・フォント・CDN・ブラウザからの状態書き換えはない。

## 更新

1. [tasks.json](tasks.json)の小項目の`status`、`evidence`と、`updatedAt`、`currentStep`、`currentTaskId`、`activity`を更新する。証拠に対象版・日付・確認方法・結果・限界を記録する。
2. 順序・範囲の変更は[roadmap.md](../roadmap.md)、公開MVPの変更は[mvp.md](../mvp.md)へ反映する。API/DB/検証手順の正本も変更対象に応じて更新する。
3. `pnpm progress:build`で単体HTMLを生成し、`pnpm progress:check`でデータ・文書・表示ソースとの一致を確認する。
4. サーバー閲覧では「最新の記録を読み直す」で更新する。HTMLを直接開く場合は、再生成後に読み直す。

`template.html`、`style.css`、`client.js`は表示ソース、`index.html`は生成物。生成HTMLを直接編集しない。任意の資料や環境ファイルを読み込まず、生成スクリプトに列挙したMarkdownだけを埋め込む。

## 状態と集計

| 値 | 表示 | 意味 |
| --- | --- | --- |
| todo | 未着手 | 基準版の計画上の残件。別ブランチの着手状況とは別 |
| doing | 対応中 | 小項目を作業中 |
| verify | 検証待ち | 実装または設計準備が存在するが、完了条件の確認が残る |
| done | 完了・根拠あり | 記載した範囲の完了条件と証拠が揃う |
| blocked | 要判断・保留 | 具体的な判断や修正が必要 |

完了率は`done / 全小項目`の四捨五入。対応中・検証待ちに部分点を付けず、階層を重複加算しない。工数や日数ではない。無料βまで（STEP 01〜05）と全計画を分けて表示する。工程は配下の全小項目が完了したときだけ完了とする。

初期の完了項目は現在地の静的棚卸しであり、実DBや本番の合格を示さない。Issue/PRの状態、ローカル検証、外部公開の確認は別々に記録する。公開前ゲートは別表示し、STEPのローカル準備と重複集計しない。

`progress:check`は重複ID、空の工程、状態値、完了根拠の欠落、証拠参照、現在項目、ローカル参照先、生成物の不一致を検査する。証拠の内容の正しさや本番の安全性を自動保証する検査ではない。

## 表示方針

ユーザー指定の`latest.html`を視覚参照とする。文字`#183c3a`、補助文字`#526964`、強調`#126c61`、境界`#d8e4df`、白い紙面、背景`#f4f7f4`。Yu Gothic UI / Yu Gothic / Meiryoを使用する。

上部に全体進捗と工程ごとの細いバー、左に工程ナビ、右に件数・今進める作業・検索・状態フィルター・展開できる大/中/小項目を置く。タブで流れ、画面/API対応、公開条件、証拠を切り替える。PCは左揃えの2列、スマホは工程ナビを横並びにし、本文を1列にする。状態は色と文字で示し、キーボードフォーカスと動きの抑制を用意する。

参考リポジトリの方法と適用範囲は[ロードマップ](../roadmap.md)に記録。表示コードはStudyQuest向けに作成し、アプリのデザインは今回変更しない。

今回の表示・操作と所定チェックの結果は[確認記録](review/README.md)を参照。
